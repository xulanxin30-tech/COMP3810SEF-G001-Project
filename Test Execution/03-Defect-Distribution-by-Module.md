# Defect Distribution by Module

The session and login area has four defects, including the two worst ones. The login logic itself is fine — wrong passwords, duplicate sign-ups and bad usernames all return the right status — but passwords are stored as plain text, the fallback signing key is public, the login form drops the `next` parameter, and the sign-up password box is type="text". The book pages have three defects, all caused by missing input checks: a bad regex, an invalid ObjectId, and Mongoose validation errors all end up as 500s. The API router is the cleanest part of the code; it already checks ObjectIds and returns proper 404s, so the web pages should simply copy that pattern.

The other defects sit outside the running code. package.json points `main` at an index.js that does not exist, SECURITY.md is still the GitHub template with fake version numbers, .env.example still talks about Facebook OAuth whose routes were deleted, and the README Scope section lists exclusions as if they were features. Overall the structure is good for a first server-side project — clear folders, no committed secrets, a health endpoint and central error handlers — but error handling is inconsistent between the web routes and the API, and there was no final review pass after all the small merges.
