# Project Status and Gap Analysis

The main branch is a working MVP. A seeded user can log in, see three books, search them, add and edit a book, and drive the REST API with curl. The folder layout is clean, setup is documented, and no secrets are committed. Compared with a real cloud service, the biggest gap is security: passwords are plain text and the session key has a public fallback. A released system would hash passwords, keep the signing key in the environment, and refuse to start without it. The rest of the authentication code is actually reasonable, so this gap is only a few hours of work.

The other gaps are smaller. Input is validated by the browser and by Mongoose but not at the route boundary, so bad input becomes a 500 instead of a clean 400. The API is called /api/items and uses a task-style model that has nothing to do with books — fine for curl practice, but a real library service would use /api/books with pagination. There is no process manager, TLS or database-aware health check on the VM. There are no automated tests, and the written docs have drifted from the code. We also have six people listed with one marked as a free rider, so the real work was done by five. For a student group this is normal, and most of these gaps close with a short cleanup pass rather than a redesign.
